2. ESTRUTURA DE DADOS (BANCO DE DADOS)
================================================================================

O projeto utiliza um banco de dados em memória (localStorage) com os seguintes 
objetos principais:

2.1 PROFISSIONAIS (DB.profissionais)
─────────────────────────────────────
Propriedades:
- id: string identificador único (ex: 'p1', 'p2', 'p-paulo')
- nome: string com nome completo
- tecnologia_principal: string (ex: 'Backend Lead', 'Frontend', 'QA')
- email: string com email
- senha: string com senha (em produção usar hashing)
- perfil_acesso: string ('administrador', 'gestor', 'desenvolvedor', 'qa')
- anotacoes: array de objetos com histórico de atividades

Exemplo:
{
  id: 'p-paulo',
  nome: 'Paulo Spagolla',
  tecnologia_principal: 'Administrador',
  email: 'spagolla@gmail.com',
  senha: 'teste123',
  perfil_acesso: 'administrador'
}

2.2 CLIENTES (DB.clientes)
──────────────────────────
Propriedades:
- id: string (ex: 'cli-pp2', 'cli-san')
- nome: string com nome do cliente
- contato: string com informações de contato

Clientes Atuais:
1. Cliente Teste .Ponto (id: cli-pp2)
2. Cliente Teste Gold (id: cli-san)
3. Cliente Teste (id: cli-teste)

2.3 PROJETOS (DB.projetos)
──────────────────────────
Propriedades:
- id: string (ex: 'proj-pp2')
- nome: string nome do projeto (sigla)
- cliente_id: referência ao cliente
- cor_hex: string com cor em hexadecimal para UI
- sigla: string curta (ex: 'CP', 'God', 'TST')
- status: string ('ativo', 'pausado', 'concluido')
- equipe: array com profissionais e seus papéis no projeto
  - profissional_id: referência ao profissional
  - perfil: string descrevendo o papel (ex: 'Backend Lead')
  - alocacao_pct: número 0-100 (% de dedicação, opcional)

Projetos Atuais:
1. CP (Cliente Teste .Ponto)
   - Sigla: CP
   - Status: ativo
   
2. God (Cliente Teste Gold)
   - Sigla: God
   - Status: ativo
   
3. Teste (Cliente Teste)
   - Sigla: TST
   - Status: ativo
   - Projeto de validação 100% dedicado

2.4 SPRINTS (DB.sprints)
─────────────────────────
Propriedades:
- id: string (ex: 'sp-pp2-sprint-1')
- nome: string (ex: 'CP Sprint 1')
- duracao_semanas: número
- projeto_id: referência ao projeto
- status: string ('planejada', 'em_andamento', 'concluida')
- objetivo: string descrevendo o objetivo da sprint

Sprints Atuais:
- CP Sprint 1, 2, 3 (projeto CP)
- God Sprint 0 (projeto God)
- Teste Sprint 1, 2, 3 (projeto Teste)

2.5 HISTÓRIAS (DB.historias)
────────────────────────────
Propriedades:
- id: string (ex: 'PP2-1', 'TST-1')
- titulo: string descritivo
- projeto_id: referência ao projeto
- sprint_id: referência à sprint
- cor_hex: string cor para visualização
- status: 'planejada', 'em_progresso', 'em_review', 'concluida' (calculado)

Exemplo:
{
  id: 'CP-5',
  titulo: '[US-02] Remoção de Marcações com Borracha',
  projeto_id: 'proj-pp2',
  sprint_id: 'sp-pp2-sprint-1',
  cor_hex: '#E3ABAB'
}

2.6 SUBTAREFAS (DB.subtarefas)
──────────────────────────────
Propriedades:
- id: string (ex: 'PP2-1.T1', 'CP-1.T2')
- historia_id: referência à história
- projeto_id: referência ao projeto
- sprint_id: referência à sprint
- titulo: string descritivo da subtarefa
- responsavel_id: profissional responsável
- tipo: 'Code', 'Test', 'Review', 'Design' etc
- status: 'planejada', 'progresso', 'bloqueada', 'concluida'
- progresso_pct: 0-100
- depende_de_ids: array de IDs de subtarefas que são pré-requisito
- turno_estimado: 'manha', 'tarde', 'noite'
- data_inicio_real: data (se começou)
- duracao_turnos: quantos turnos leva para completar
- pausada_motivo: motivo da pausa (se aplicável)

Exemplo:
{
  id: 'CP-1.T1',
  historia_id: 'CP-5',
  projeto_id: 'proj-pp2',
  sprint_id: 'sp-pp2-sprint-1',
  titulo: 'Implementar função de borracha',
  responsavel_id: 'p1',
  tipo: 'Code',
  status: 'progresso',
  progresso_pct: 75,
  depende_de_ids: [],
  turno_estimado: 'manha',
  duracao_turnos: 2
}

2.7 GRADE DE CRONOGRAMA (DB.grade)
───────────────────────────────────
Propriedades:
- Organizada por: Data, Turno (Manhã/Tarde/Noite), Profissional
- Cada entrada marca qual subtarefa está agendada para quando/quem
- Permite visualizar capacidade de cada profissional
- Identifica conflitos e sobrecargas

4. REGRAS DE NEGÓCIO
================================================================================

4.1 REGRAS DE STATUS
────────────────────

Histórias:
- Planejada: Criada, na sprint, nenhuma subtarefa iniciada
- Em Progresso: Pelo menos 1 subtarefa iniciada
- Em Review: Todas as subtarefas em review ou concluídas
- Concluída: Todas as subtarefas concluídas

Subtarefas:
- Planejada: Criada, não iniciada
- Em Progresso: 1-99% de progresso (0 < prog < 100)
- Bloqueada: Aguardando dependência ou bloqueada por outro motivo
- Concluída: 100% de progresso

Sprints:
- Planejada: Criada, data de início no futuro
- Em Andamento: Data atual está dentro da duração
- Concluída: Data de término passou

4.2 REGRAS DE DEPENDÊNCIAS
───────────────────────────

- Uma subtarefa pode depender de outras subtarefas
- Se uma subtarefa depende de outra não concluída, fica bloqueada automaticamente
- Não é permitido criar dependência cíclica (A → B → A)
- Ao desbloquear uma subtarefa, suas dependentes podem ser desbloqueadas

4.3 REGRAS DE ALOCAÇÃO
──────────────────────

- Um profissional pode ser alocado em múltiplos projetos
- Cada projeto tem um % de dedicação recomendado (100% total ideal)
- Alocação é controlada via perfil na equipe do projeto
- Sistema avisa se profissional está sobrecarregado (>100%)

4.4 REGRAS DE CRONOGRAMA (LEGO)
────────────────────────────────

- Cada profissional tem 3 turnos/dia: Manhã, Tarde, Noite
- Cada subtarefa é agendada para um turno específico
- Uma célula (prof + dia + turno) só pode ter 1 subtarefa
- Pode haver múltiplas subtarefas do mesmo responsável em dias diferentes
- Sistema impede agendar subtarefa bloqueada

4.5 REGRAS DE PROGRESSO
───────────────────────

- Progresso é manual (entrada do usuário)
- Quando subtarefa atinge 100%, transita para status apropriado
- Histórias calculam progresso como média de suas subtarefas
- Dashboard mostra progresso em tempo real

4.6 REGRAS DE ACESSO
────────────────────

- Perfil Administrador: Acesso a TUDO
- Perfil Gestor: Sem acesso a CADASTRO (não pode criar/editar profissionais)
- Perfil Desenvolvedor: Leitura em PROJETOS, acesso total em MINHA ÁREA
- Perfil QA: Igual desenvolvedor com ênfase em testes

- Cada usuário só vê suas tarefas em MINHA ÁREA (exceto gestor/admin)
- Admin pode ver histórico completo de todas anotações

5. FLUXOS DE TRABALHO
================================================================================

5.1 FLUXO DE CRIAÇÃO DE PROJETO
────────────────────────────────

1. Admin vai a CADASTRO → Cadastro de Projetos
2. Clica em "+ Novo Projeto"
3. Preenche:
   - Nome (sigla)
   - Cliente (select)
   - Cor (hexadecimal ou picker)
   - Status (ativo/pausado)
4. Confirma criação
5. Sistema cria ID automático (proj-xxx)
6. Pode adicionar profissionais à equipe imediatamente

5.2 FLUXO DE CRIAÇÃO DE SPRINT
───────────────────────────────

1. Vai a CADASTRO → Cadastro de Sprints
2. Clica em "+ Nova Sprint"
3. Preenche:
   - Nome (ex: "CP Sprint 4")
   - Projeto (select)
   - Duração em semanas (ex: 2)
   - Objetivo (descrição)
4. Data de início é a data de criação
5. Sistema calcula data de término: inicio + (duracao_semanas * 7)
6. Status muda automaticamente conforme data

5.3 FLUXO DE CRIAÇÃO DE HISTÓRIA
─────────────────────────────────

1. Vai a PROJETOS → Seleciona Projeto → Aba SPRINTS
2. Expande uma Sprint
3. Clica em "+ Nova História"
4. Preenche:
   - ID (auto-gerado ou manual)
   - Título (ex: "[US-01] Cadastro de Usuário")
   - Cor (auto-gerada aleatória ou escolhida)
5. Confirma
6. História criada em status "planejada"
7. Agora pode adicionar subtarefas

5.4 FLUXO DE CRIAÇÃO DE SUBTAREFA
──────────────────────────────────

1. Va a PROJETOS → Seleciona Projeto → SPRINTS
2. Expande Sprint → Expande História
3. Clica em "+ Nova Subtarefa"
4. Preenche:
   - Título (ex: "Implementar endpoint de login")
   - Responsável (select de profissionais)
   - Tipo (Code/Test/Design/Review)
   - Turno estimado (manha/tarde/noite)
   - Duração em turnos (1, 2, 3...)
   - Dependências (if any)
5. Confirma
6. Subtarefa criada em status "planejada"

5.5 FLUXO DE AGENDAR NO CRONOGRAMA
──────────────────────────────────

1. Vai ao menu LEGO
2. Procura célula vazia (prof + dia + turno)
3. Clica na célula
4. Sistema abre modal com:
   - Subtarefas disponíveis para agendar daquele profissional
   - Que não estão bloqueadas
   - Que cabem no turno/duração
5. Seleciona subtarefa
6. Sistema marca a(s) célula(s) com a subtarefa
7. Subtarefa transita para status "em progresso"

5.6 FLUXO DE ATUALIZAR PROGRESSO
──────────────────────────────────

1. Usuário vai a MINHA ÁREA (Kanban)
2. Clica em uma subtarefa
3. Abre modal de detalhes
4. Atualiza "Progresso %" (0-100)
5. Clica em Atualizar
6. Sistema recalcula:
   - Status da subtarefa (baseado em %)
   - Status da história (média das subtarefas)
   - Progresso visível em tempo real

5.7 FLUXO DE BLOQUEAR/DESBLOQUEAR
──────────────────────────────────

Para Bloquear:
1. Vai a MINHA ÁREA ou PROJETOS
2. Clica em subtarefa
3. Seleciona "Marcar como Bloqueada"
4. Insere motivo (ex: "Aguardando aprovação do design")
5. Confirma
6. Subtarefa fica com status "bloqueada" (ícone de cadeado)

Para Desbloquear:
1. Mesmo local
2. Clica "Desbloquear"
3. Sistema verifica dependências
4. Se OK, muda status para último (em progresso/planejada)

5.8 FLUXO DE NAVEGAR DO LEGO PARA PROJETOS
─────────────────────────────────────────────

1. Usuário está no menu LEGO
2. Clica em qualquer quadro (subtarefa agendada)
3. Sistema:
   - Muda para menu PROJETOS
   - Seleciona automaticamente o Projeto correto
   - Abre aba SPRINTS
   - Expande a Sprint automaticamente
   - Expande a História automaticamente
4. Usuário vê todas as subtarefas da história abiertas

Autenticação:

3. Armazenar usuário atual em estado global
4. Verificar perfil de acesso para mostrar/ocultar menus

Cálculos:
1. Status história = MAX(status das subtarefas)
2. Progresso história = AVG(progresso % das subtarefas)
3. Sprint em_andamento se hoje está entre data_inicio e data_fim

9. GLOSSÁRIO
================================================================================

LEGO: Menu de cronograma/grade (Plano de Turno)
Sprint: Período de 1-4 semanas de desenvolvimento
História: User Story (funcionalidade para o usuário final)
Subtarefa: Breakdown de uma história em tarefas técnicas menores
Turnos: Períodos do dia (Manhã, Tarde, Noite)
Responsável: Profissional alocado à subtarefa
Status: Estado atual (planejada, em progresso, bloqueada, concluída)
Dependência: Prerequisito (subtarefa A depende de B estar concluída)
Bloqueada: Impedida de avançar (por dependência ou motivo externo)
Alocação: % de dedicação de um profissional a um projeto
Kanban: Visualização de workflow em colunas (Aguardando, Dev, Review, etc)
Perfil de Acesso: Nível de permissão (Admin, Gestor, Dev, QA)
